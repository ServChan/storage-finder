# Storage Finder — technical audit

Дата аудита: 2026-07-16

Целевая версия: 1.0.0

Среда: Minecraft 26.1.2, Fabric Loader 0.19.3, Loom 1.17.12, Java 25

## Объём проверки

Проверены build-конфигурация, metadata, mixin-цели, обработка правой Alt, текстовый каталог, идентичность предметов и зачарованных книг, связывание меню с блоком, двойные сундуки, исключение эндер-сундуков, сохранение и миграции JSON, разделение серверных миров, пространственные ограничения, A*-маршруты, кэш, Gizmo-рендер, локализации, настройки Mod Menu и установленный профиль.

## Исправленные проблемы

| Важность | Проблема | Исправление |
|---|---|---|
| Critical | Миграция индекса пыталась заменить JSON, пока reader ещё был открыт. Windows возвращала `AccessDeniedException`. | Запись перенесена за пределы try-with-resources reader. |
| Critical | После неудачной записи изменённые данные оставались только в памяти, но следующий неизменный тик не повторял сохранение. | Добавлен флаг `dirty`; запись повторяется до успеха. |
| High | Текстовый поиск вручную собирал ключ, отличный от пути реального предмета в руке. | Подсказка создаёт настоящий `ItemStack` и использует общий `SearchSelection.itemIds`. |
| High | Зачарованная книга представлялась одним комбинированным ключом. | Каждое stored enchantment индексируется отдельным ключом; уровень игнорируется. |
| High | Старый комбинированный формат книг мог потеряться при обновлении. | Добавлена консервативная миграция каждого старого ключа. |
| High | Legacy-миграция при двух мирах переносила все записи после нахождения одной близкой. | Мигрируются только записи в текущем радиусе. |
| High | Автоочистка удаляла индекс, если блок временно отсутствовал в формально загруженном чанке. | Автоудаление отключено; отсутствующий блок просто не показывается. |
| High | Резервная копия создавалась, но не использовалась при повреждении или исчезновении основного JSON. | Добавлено восстановление непустого `.bak` без перезаписи валидной копии повреждённым primary. |
| High | Последовательные корректные записи могли вытеснить старый полный `.bak` после логического обнуления. | Добавлена `.recovery`, обновляемая только при росте числа известных записей; восстановление выбирает наиболее полную копию. |
| Medium | UI мог выбрать неверный одноимённый registry-вариант. | Дубликаты локализованных названий получают уточняющий ID. |
| Medium | Частичное совпадение могло стоять выше точного результата. | Добавлено ранжирование exact/start/end/word/contains. |
| Medium | При движении по маршруту A* полностью пересчитывался из-за изменения стартового блока. | Валидный хвост кэша переиспользуется, если игрок находится на пути. |
| Medium | Цель для верхнего сундука могла оказаться на этаже над ним. | Высота конечной поверхности ограничена реальным диапазоном взаимодействия сбоку. |
| Medium | Filled cuboid вызывал ошибку Iris `minecraft:pipeline/debug_filled_box`. | Подсветка переведена на stroke-only Gizmo; маршруты остаются линиями и стрелками. |
| High | Напольная бочка имела доступную поверхность на `+1`, но общий лимит цели был `+0.5`; A* видел кандидата хранилища, но не имел конечных клеток. | Для `BarrelBlock` разрешены соседний пол на `+1` и свободная клетка непосредственно над бочкой; правило сундуков не изменено. |
| High | Поставленный шалкеровый ящик открывает `ShulkerBoxMenu`, а индексатор принимал только `ChestMenu`; содержимое шалкера не запоминалось. | Снимок теперь поддерживает оба меню и читает только первые 27 storage-слотов шалкера, не затрагивая инвентарь игрока. |
| High | Неудачный A* без маршрута запускался заново каждые 0,5 секунды и мог постоянно нагружать render/client thread. | Добавлен отрицательный кэш на 10 refresh-циклов (около 5 секунд) для неизменной позиции и целей; движение немедленно инвалидирует его. |
| Medium | Правило `+1` применялось ко всем бочкам и могло снова выбрать этаж над горизонтальной настенной бочкой. | Верхняя цель разрешена только для бочки с `FACING=UP`. |
| Medium | После клика по хранилищу неподдерживаемое контейнерное меню могло оставить pending-позицию для следующего экрана. | Любое открывшееся контейнерное меню поглощает pending association; индексирование начинается только при совпадении физического блока и типа меню. |
| Medium | Экран настроек показывал успешный toast даже при ошибке записи JSON. | `StorageFinderConfig.save` возвращает результат; при ошибке экран остаётся открыт и показывает отдельный error-toast. |
| Low | Закрытие настроек из Mod Menu во время игры возвращало сразу в игру. | Экран всегда возвращается к переданному родительскому экрану. |
| Low | Категория назначения клавиши использовала неверный translation key `key.categories...`. | Ключ исправлен на фактически запрашиваемый Minecraft `key.category.storagefinder.main`. |
| High | Полный A* до 40 000 узлов выполнялся за один вызов на client thread и мог создать заметный frame-time spike. | Поиск преобразован в сохраняемую state machine с общим бюджетом 800 узлов на тик; до трёх целей вычисляются последовательно без блокирующего цикла. |
| Medium | Игрок не видел, активен ли запрос, сколько найдено хранилищ и почему отсутствует линия. | Добавлена постоянная нижняя левая HUD-панель со статусами `нет рядом`, `расчёт`, `нет пути` и количеством готовых маршрутов. |
| Medium | Для выбранной из руки зачарованной книги HUD мог показать только общее имя предмета. | Display-query хранит настоящий `ItemStack` и локализованный список конкретных чар. |
| Medium | Уведомление могло заявлять о сохранении после ошибки диска. | `UpdateResult` содержит `persisted`; пользователю показывается ошибка и обещание повтора. |
| Low | Metadata допускала Minecraft новее 26.1.2. | Зависимость закреплена на `minecraft: 26.1.2`, loader — от 0.19.3. |
| Low | Имелись неиспользуемые публичные методы. | Мёртвый код удалён. |

## Подтверждённые API

Через `javap` против Loom jar 26.1.2 подтверждены:

- `MultiPlayerGameMode#useItemOn(LocalPlayer, InteractionHand, BlockHitResult)`;
- `ClientPacketListener#handleLogin(ClientboundLoginPacket)`;
- `ClientPacketListener#handleRespawn(ClientboundRespawnPacket)`;
- `AbstractContainerScreen#removed()`;
- `ClientboundLoginPacket#commonPlayerSpawnInfo()`.
- `ShulkerBoxMenu` с 27 начальными storage-слотами и отдельным от `ChestMenu` типом меню;
- `BarrelBlock#FACING` для различения напольной и горизонтальной бочки.

Mixin JSON использует `required: true`, `defaultRequire: 1` и `compatibilityLevel: JAVA_17`; ошибки сигнатур не будут скрыты.

## Проверка сборки

Команда:

```powershell
.\gradlew.bat clean build --warning-mode all
```

Результат после исправлений: `BUILD SUCCESSFUL`, Java compiler warnings отсутствуют, `check` и `validateAccessWidener` завершены.

Дополнительно проверены:

- одинаковый набор ключей `ru_ru.json` и `en_us.json`;
- версия `1.0.0` внутри собранного `fabric.mod.json`;
- ровно один активный JAR мода в тестовом профиле после установки;
- отсутствие устаревших API-маркеров (`WorldRenderEvents`, `ResourceLocation`, Mojang mappings, `hasChunkAt`).

## Runtime-наблюдения

До исправления в раннем runtime-логе подтверждён `AccessDeniedException` при миграции индекса на Windows. В crash-report от 20:39 присутствует `StorageSearchScreen`, но первопричина — `ZipFile invalid LOC header`: JAR был заменён во время работы клиента, а JVM позднее попыталась дочитать внутренний класс из уже изменённого ZIP. Это операционная ошибка обновления, а не исключение каталога. Последующий чистый запуск в `latest.log` загрузил Storage Finder 1.0.0 без его исключений.

Текущий профильный индекс валиден: primary содержит 98 записей, backup — 97, recovery — 98; все три JSON успешно разобраны. В профиле обнаружена одна scope, что соответствует посещённому после внедрения world-scope миру и не доказывает игровой переход во второй мир.

Новая аудитная сборка проверена компиляцией и статическим анализом. Полный интерактивный прогон после последних изменений не заявляется как выполненный.

## Оставшиеся ограничения

1. Клиент не может прочитать содержимое закрытого контейнера до его открытия.
2. Если сервер сообщает одинаковые address, dimension ID и seed для двух логически разных миров, стандартный клиентский протокол не даёт надёжного дополнительного world ID.
3. A* остаётся на клиентском потоке, но ограничен общим бюджетом 800 узлов на тик и лимитом 40 000 узлов на попытку. Очень сложный маршрут может рассчитываться несколько секунд или завершиться без результата, сохранив подсветку.
4. Маршрут не моделирует двери, лестницы, плавание, полёт и сложный паркур.
5. Для окончательной проверки требуются игровые сценарии из следующего раздела.

## Рекомендуемый игровой regression-check

1. Правая Alt с обычным предметом в руке: правильная подсветка и до трёх маршрутов.
2. Правая Alt с пустой рукой: ввод, русский поиск, выбор мышью и Enter.
3. Сравнить INFO-ключи одного предмета из руки и из текста — они должны совпадать.
4. Поиск «Шипы» не должен показывать сундук только с «Починкой».
5. Книга с несколькими чарами должна находиться по каждому виду чар.
6. Открытие найденного сундука должно убрать только совпавший запрос.
7. Верхний сундук в ряду не должен вести на этаж сверху.
8. Ковёр не должен считаться прыжком; стены и жидкости должны обходиться.
9. Закрыть игру во время открытого контейнера и проверить восстановление индекса.
10. Повредить копию primary JSON в тестовом профиле и проверить восстановление `.bak`.
11. Перейти между миром построек и миром ферм, проверить отсутствие смешивания координат.
12. Проверить, что эндер-сундук не создаёт и не обновляет запись.
13. Открыть поставленный шалкер, закрыть его, перезапустить клиент и найти предмет только по сохранённому содержимому.
14. Проверить напольную бочку с крышкой вверх и горизонтальную бочку в стене: первая допускает подход сверху, вторая не ведёт на верхний этаж.
15. Открыть настройки из Mod Menu, проверить Cancel/Save и возврат к списку модов.
16. Не перезаписывать активный JAR; обновление выполнять только после выхода из Minecraft.
17. Добавить несколько запросов и проверить нижнюю левую панель: иконки, цвета, число совпадений, `расчёт`, готовые маршруты и `нет пути`.
18. Проверить книгу из руки: HUD должен назвать конкретное зачарование, а не просто «Зачарованная книга».
19. Во время сложного расчёта проверить отсутствие длинного единичного подвисания; статус должен обновиться после завершения пошагового A*.

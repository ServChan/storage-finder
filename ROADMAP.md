# Storage Finder — предложения по развитию

Версия проекта остаётся `1.0.0` до отдельной команды владельца. Ниже — предложения, а не обещанные или уже реализованные функции.

## Реализовано после аудита

1. **Постоянная панель активных запросов.** Нижний левый HUD показывает иконку, локализованное имя, цвет, число найденных хранилищ и состояние маршрутов. Удаление выполняется через уже существующий список активных запросов в каталоге.
2. **Диагностика маршрута в HUD.** Реализованы состояния отсутствия совпадений, текущего расчёта, отсутствия достижимого пути и числа готовых маршрутов.
3. **Инкрементальный pathfinding.** A* хранит состояние между тиками и получает общий бюджет 800 узлов за тик.

По решению владельца экран управления индексом и различение источника «рамка/память» пока не нужны.

## P1 — возможное дальнейшее улучшение

1. **Разделы «Активные» и «Добавить» в поиске.** Активные запросы можно вынести в отдельный постоянный список, а каталог сделать независимо прокручиваемым. Полезны multi-select без закрытия экрана и отдельная кнопка «Готово».
2. Более подробные причины неудачи A*: лимит узлов, незагруженный чанк или отсутствие конечной клетки.

## P2 — качество маршрута и поиска

1. Поддержка открытых дверей, лестниц и безопасных люков как отдельных типов переходов.
2. Пересчёт маршрута по событиям изменения ближайших блоков, а не только по таймеру.
3. Расстояние до каждого совпадения и возможность вручную закрепить одну из трёх целей.
4. Настраиваемые толщина/прозрачность линий, частота точек и режим «только стрелки».
5. Палитры для дальтонизма и различимые штриховки/значки, чтобы запросы отличались не только цветом.

## P3 — расширения

1. Необязательный серверный companion-мод/плагин с разрешениями, который легитимно публикует индекс закрытых хранилищ. Чистый клиент получить эти данные не может.
2. Поддержка дополнительных контейнеров модов через безопасный registry/config allowlist.
3. Кнопка перехода прямо к назначению клавиши из Mod Menu и предупреждение о конфликте привязок.
4. Диагностический экран world-scope: server address, dimension и seed-marker, чтобы видеть, почему два серверных мира разделены или конфликтуют.

## Рекомендуемый порядок

Следующий наиболее полезный шаг — более подробная причина неудачи маршрута и отдельный прокручиваемый раздел активных запросов. Управление индексом отложено как ненужное для текущего игрового сценария.

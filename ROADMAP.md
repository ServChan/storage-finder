# Storage Finder — предложения по развитию

Версия проекта остаётся `1.0.0` до отдельной команды владельца. Ниже — предложения, а не обещанные или уже реализованные функции.

## P1 — максимальная практическая польза

1. **Компактная панель активных запросов.** Иконка, локализованное имя, цвет, число найденных хранилищ, число доступных маршрутов и кнопка удаления. Это сразу объяснит состояние «предмет выбран, но рядом ничего нет» без повторного открытия каталога.
2. **Разделы «Активные» и «Добавить» в поиске.** Активные запросы должны оставаться отдельным постоянным списком, а каталог — прокручиваться независимо. Полезны multi-select без закрытия экрана и отдельная кнопка «Готово».
3. **Диагностика маршрута в HUD.** Состояния «3 совпадения / 0 достижимых», «цель за пределами загруженных чанков», «превышен лимит A*» и «повтор через N секунд». Сейчас отсутствие линии визуально неоднозначно.
4. **Инкрементальный или фоновый pathfinding.** Делить A* на небольшой бюджет узлов за тик и публиковать результат только после завершения. Это устранит единичные frame-time spikes при сложных складах.
5. **Экран управления индексом.** Фильтр по серверу/миру, число контейнеров, время последнего обновления, ручное удаление stale-записи, экспорт, импорт и явное восстановление из `.bak`/`.recovery`.

## P2 — качество маршрута и поиска

1. Поддержка открытых дверей, лестниц и безопасных люков как отдельных типов переходов.
2. Пересчёт маршрута по событиям изменения ближайших блоков, а не только по таймеру.
3. Метка источника совпадения: **рамка**, **память** или **оба**, плюс возраст запомненного снимка.
4. Расстояние до каждого совпадения и возможность вручную закрепить одну из трёх целей.
5. Настраиваемые толщина/прозрачность линий, частота точек и режим «только стрелки».
6. Палитры для дальтонизма и различимые штриховки/значки, чтобы запросы отличались не только цветом.

## P3 — расширения

1. Необязательный серверный companion-мод/плагин с разрешениями, который легитимно публикует индекс закрытых хранилищ. Чистый клиент получить эти данные не может.
2. Поддержка дополнительных контейнеров модов через безопасный registry/config allowlist.
3. Кнопка перехода прямо к назначению клавиши из Mod Menu и предупреждение о конфликте привязок.
4. Диагностический экран world-scope: server address, dimension и seed-marker, чтобы видеть, почему два серверных мира разделены или конфликтуют.

## Рекомендуемый порядок

Сначала панель активных запросов и понятные статусы маршрута, затем инкрементальный A*, после этого управление индексом. Эти три изменения сильнее всего улучшают повседневный UX и диагностируемость без серверной части.
